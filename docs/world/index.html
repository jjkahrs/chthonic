Chthonic World Server

MMORPG world server for Chthonic, written in C++20. It covers the following:

  • Connections: clients connect over TLS-over-TCP and log in with an access token from the auth service.
  • Characters: clients create, list and delete characters, then enter the map they were saved on (see "Maps").
  • Movement: the server validates every move (map bounds and max speed) and replicates it to nearby players through grid-based interest management.
  • Chat: proximity chat: "say" and emotes reach everyone in view, a "yell" everyone on the map within CHAT_YELL_RADIUS. Whispers, channels and the zone channel are the realm's chat service's; the world tells it who is online on which map over an internal link and drops a muted character's proximity chat.
  • Lua: game-defined components, state machines and server-authoritative systems on the tick, persisted per character and replicated to clients (see "Lua components and systems").
  • NPCs: server-authoritative NPCs come from per-tile spawn files (with respawn timers and patrol paths) or from Lua systems, which move and destroy them; they reach players through the same interest management, with their components and state machines (see "NPCs" and "NPC spawns").
  • Architecture: an EnTT ECS runs on a fixed 20 Hz tick on one game thread, which also handles every client message. TLS and socket I/O run on NET_THREADS net threads (default 4), and characters persist to MySQL on DB worker threads, so the tick never waits on the network or the database.

The wire format is in Protocol; how to write a game client against it, end to end, is in the Client implementer guide.

Dir What
protocol/ Static lib: frame codec, opcodes and message structs. No Asio, DB or ECS, so a game client can reuse it
map/ Static lib chthonic_map: map.json parsing and tile math. Standard library + nlohmann_json only, no file IO, so the tools and the bot can reuse it
server/ chthonic_world: core/ (config, log, clock, limits, chat rules), net/ (TLS, sessions), auth/ (JWKS, JWT), db/ (MySQL, migrations, worker), world/ (ECS components and systems), lua/ (Lua sandbox, component and state machine definitions, systems runtime, event bus, state machines), app/ (glue, the chat link). service_core.cmake builds the part the chat service shares (chthonic_service_core: core/ env, log, chat rules; net/; auth/; db/ MySQL and migrations) and chthonic_protocol
bot/ chthonic_bot: headless test client covering auth HTTP, Mailpit verification, TLS, scripted scenarios and load mode
migrations/ NNN_name.sql, applied in order at startup
lua/ Sample Lua components, state machines and systems (LUA_ROOT in the image)
tests/ self_check.cpp + lua_checks.cpp (ctest), integration.sh, load.sh, docs_check.sh
